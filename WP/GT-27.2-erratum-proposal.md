# Proposal — CONVENTIONS.md §27.2 implementation note (v0.6 erratum, **no version bump**)

**Status:** propose-don't-apply. The implementation note below is to be **appended to
`CONVENTIONS.md` §27.2 by the maintainer** (a sealed-section edit). **No `CONVENTION_VERSION`
bump** — it stays `0.6`: the mathematical definition (`V + iΩ ≥ 0`; for a real, symmetric,
PSD candidate ⇔ `ν_i ≥ 1`) is **unchanged**; the note only records that the *implementation*
evaluates the equivalent `V ⪰ 0 ∧ ν_i ≥ 1` realisation. **No test change** — the behaviour is
already the Williamson form, pinned by `tests/unit/test_gaussian_toolbox.py`
(`test_is_physical_is_scale_and_correlation_invariant`) and `tests/conventions/test_gaussian_conventions.py`.

**Dispatch:** post-GT1-hardening erratum · **Drafted:** 2026-07-15 · **Author stance:** Guardian.

**Why.** The GT1 numerical hardening (`5f7c04a` + review follow-up `c885e86`) made `is_physical`
evaluate §27.2's own *"for a real, symmetric, PSD candidate, physicality is equivalent to
`ν_i ≥ 1`"* equivalence, because a direct absolute-tolerance test on the entries of `V + iΩ` is
**not** numerically scale- or correlation-invariant — two adversarial-verify passes defeated it
(a scale-asymmetric `diag(1e9, 2.5e-10)` and a strongly-correlated `[[c,d],[d,c]]`, both `ν = 0.5`,
each shrink the `V + iΩ` violation below any fixed tolerance while `ν` stays below 1). That leaves
the sealed §27.2 sentence *"the implementation therefore always uses the direct Hermitian PSD
guard"* factually inconsistent with the code. Per the maintainer's decision (erratum, no bump),
this note reconciles the authoritative prose with the robust realisation, so code and convention
are not knowingly contradictory going into GT4.

## Edit — append to the end of §27.2

**Where:** in `CONVENTIONS.md`, at the end of **§27.2 (Symplectic form and physicality)**,
immediately after the sentence *"…the implementation therefore always uses the direct Hermitian
PSD guard."*

**Insert verbatim:**

```markdown
**Implementation note (v0.6 erratum, 2026-07-15).** A direct absolute-tolerance test on the
entries of `V + iΩ` is not numerically scale- or correlation-invariant: a scale-asymmetric or
strongly-correlated `V` can shrink a genuine `V + iΩ` violation below any fixed tolerance while
the symplectic invariant `ν` stays below 1. The physicality predicate (`is_physical`) therefore
evaluates the **mathematically equivalent** criterion for a covariance candidate — `V ⪰ 0`
(which rejects the indefinite case a bare `ν ≥ 1` would miss) together with `ν_i ≥ 1` — realising
the same `V + iΩ ≥ 0` physicality robustly. This is an implementation clarification only; the
mathematical definition above is unchanged, and no `CONVENTION_VERSION` bump is implied.
```
