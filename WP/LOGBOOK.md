## Purpose *(Sail)*

This is the **single dated stream** of how the project actually went: the decisions, the rationale, the options rejected, the dead-ends, the deferrals, the dispatch-code minting, and the release-cut events. It exists because, before it, that narrative was reconstructed from three incompatible places — WORKPLAN `§`-amendments, design-note `§`-additions, and git commit bodies — and the dead-ends and null results were buried in prose or lost entirely.

**What the logbook captures that nothing else does:**

- **Decision rationale and alternatives rejected,** chronologically, in one place.
- **Open-question lifecycle** across the whole repo (question ID, opened-on, status, resolution, where the spec changed) — not just inside one design note.
- **Dead-ends, deferrals, and null results** — the things `CHANGELOG.md` structurally cannot hold, because it is *Added / Changed / Fixed* only. (e.g. "post-α GPU open-system branch deferred indefinitely under the Q6 resolution"; "jax-metal 0.1.1 incompatible with jax 0.10.0 — local M1 cannot serve as the GPU reference" — these belong here.)
- **The release-cut procedure and its per-release SemVer justification,** so it stops being archaeology recoverable only from commit bodies.
- **The dispatch-code registry** — code → title → WP → status → carrier — so codes do not collide and "what shipped when" is answerable in one place.
- **Cross-repo decisions** referencing `cd-rules`, the `single-25Mg-plus` twin, or the two-repo hosting model (`§4.0`).

### Reconciliation with CHANGELOG — read this once *(Coastline gate)*

- **CHANGELOG = what shipped.** Keep-a-Changelog, dispatch-indexed, *Added / Changed / Fixed*, per-release summary + test counts. Outcome only. Binding surface record.
- **LOGBOOK = why it went that way.** Narrative, dated, append-only. Holds rationale, rejected options, Q-resolutions, dead-ends, deferrals, release-cut events, code minting — none of which the CHANGELOG can or should hold.

If a line says "function X added, tests pass", it is a CHANGELOG line. If a line says "we chose X over Y because Z, and Y is deferred until a real case lands", it is a logbook line. **Never duplicate the CHANGELOG here**; link to it.

## Entry format *(Sail)*

Append entries newest-last under `## Entries`. Each entry:

```
### YYYY-MM-DD — <short title>

- **Refs:** WP-NN · Dispatch <CODE> · TC-<ID> · §5.x · Q<n>   (whichever apply)
- **Stance:** Guardian | Architect | Scout | Integrator   (only if a stance framed the call; omit otherwise)
- **What:** one or two sentences — the decision or event.
- **Why:** the rationale, and the options rejected (name them).
- **Outcome:** landed / deferred / null result / open; where the spec changed.
- **Links:** CHANGELOG bullet, WORKPLAN amendment, design note §, commit, card.
```

Keep entries short and honest. A null result is a first-class entry — label it as one. Originally-recorded entries are never rewritten; a later correction is a *new* entry that reads back through the old one (honesty discipline, carried from the WORKPLAN).

Its binomial sampling is self-contained (consumes no measurement-layer public API), so the choice is clean.

### 2026-07-15 — GT3a landed: generic symplectic congruence (partial GT3)

- **Refs:** WP-07 · GT3a (a **partial** GT3 slice — GT3b, the ion `S`-adapter, stays open) · §27.4 (observable-only, no convention bump — `CONVENTION_VERSION` stays `0.6`).
- **Stance:** Architect (the application-agnostic congruence — the two-ion Phase B dependency; the ion `S` stays out) with a Guardian check (no masses / mode eigenvectors / local frequencies / `ModeConfig` coupling in `gaussian.py`).
- **What.** Added `congruence(S, V) = S V Sᵀ` for a symplectic `S` (`S Ω Sᵀ = Ω`), preserving the Williamson spectrum `ν_i` (hence purity/entropy/physicality) — a squeeze/rotation/beamsplitter reshapes `V` without changing mixedness. Validates `S` real/finite/square `2N×2N` matching `V`, and both input and output as bona-fide physical covariances (the output carrying the honest `cond ≳ 1e12` guard). Per the maintainer's boundary this is **explicitly partial**: GT3 is **not** marked fully landed — the ion-specific normal→local `S` (GT3b) is a separate scoped cross-repo decision kept **out** of the module. New module constant `_SYMPLECTIC_RELATIVE_TOL = 1e-11`.
- **Why (worth recording — a 4-round adversarial hardening of the symplecticity gate).** The maintainer asked to "check `SΩSᵀ = Ω` with a scale-aware **relative** tolerance." Four adversarial-verify workflows each found a real weakness in successive gate designs:
  1. **Global `‖S‖²` budget → block-defeat.** A single `1e-9·‖S‖²` tolerance let one large symplectic block (a strong squeeze `diag(λ, 1/λ)`) inflate the budget for a small non-symplectic block beside it (the multimode normal→local regime GT3b targets). **Fix:** a **per-entry** relative test — each residual entry against `‖row_i(S)‖·‖row_j(S)‖` (Cauchy–Schwarz bound, Ω orthogonal; floored at 1). Block-local by construction.
  2. **Entangling large-norm bypass.** A strong two-mode squeezer (`r = 6`, all rows ≈ 285) with one corrupted entry carries a `~7e-5` Ω-violation that the per-entry budget still swallows (relative `9e-10 < 1e-9`). *(I first added an **absolute cap** at 1% of the physicality margin — later removed, see round 3.)*
  3. **The absolute cap was wrong both ways.** (a) It **false-rejected genuine strong squeezes**: `R(45°)·diag(e¹², e⁻¹²)·R(45°)ᵀ` is exactly symplectic (relative `1.7e-16`) yet its *absolute* `|SΩSᵀ−Ω|` reaches `~2e-6` from `e^{2r}` catastrophic cancellation. (b) It **could not bound the damage** it claimed to: the ν-shift a near-symplectic `S` inflicts on an ill-conditioned (squeezed) `V` grows `~√cond(V)` — mpmath-verified `6.2e-4` ν-shift from a `3e-7` residual on a `cond 1.6e5` `V`, 6× past the margin. **Fix:** **remove the absolute cap**; keep the per-entry **relative** gate but **tighten** it to `1e-11` — genuine maps (incl. `r = 12` squeezes and deep 800-factor products) sit at `≤ ~1.3e-14` (`~2N·eps`, ‖S‖-independent), the near-symplectic attacks at `~7e-10`; `1e-11` splits that ~5-order gap (~750× above the genuine floor, ~70× below the attacks). The honest `cond ≳ 1e12` output guard is the `√cond` amplification backstop.
  4. **Confirmed sound.** No false-reject exists (worst genuine residual `1.3e-14`, `~750×` below the gate — the residual is `~2N·eps` independent of ‖S‖/cond, so there is structurally no headroom to reach `1e-11`). The one surviving construction — a uniform dilation `S = s·𝟙`, `det = 1+9e-12`, on a thermal `V = 1e11·𝟙` (`cond 1`, so no guard fires) → *absolute* ν-shift `0.9` — is a **relative-vs-absolute scale artifact, not a physical defect**: the *relative* ν-error is `9e-12` (purity/entropy/physicality preserved), and the absolute shift reaches `1e-4` only for `ν ≳ 1e7` (e.g. a thermal `V = 1e7·𝟙` — a perfectly valid covariance, merely **outside** this WP's validated trapped-ion operating range; `gaussian.py` is application-agnostic). **Design decision (maintainer-approved):** keep the *relative* gate. It directly guarantees only **approximate Ω-preservation**; over the certified test domain an accepted `S` is *observed* to preserve ν *relatively* to `|Δν|/ν ≲ 1e-11` — an observed/validated numerical bound, **not** a proven per-call guarantee (the output cond/physicality checks establish certifiability + physicality, not closeness to the input spectrum). This is the physically meaningful invariant (purity/entropy/physicality turn on ν relative to the vacuum floor 1) and faithful to the maintainer's "scale-aware **relative** tolerance" spec; an *absolute* cap would tie the generic toolbox to an arbitrary occupation scale and recreate the strong-squeeze false-rejects. In the operating range (`ν ≲ 1e4`) absolute preservation follows automatically (`≲ 1e-7`). A caller needing a formal *absolute* per-call guarantee compares `symplectic_eigenvalues` before/after (no extra rejection added — maintainer agreed it is unnecessary for this slice). *(Cadence note: the "adversarially-verify each slice" rail paid off again — each round caught a real defect the previous fix introduced or missed, including one I introduced (the absolute cap). Verifies ran with executed reproducers + mpmath ground truth.)*
- **Outcome.** GT3a landed; **full suite 1516 passed / 4 skipped** (all 1519 collected, tutorials included; ruff + format + mypy strict clean). *(Bookkeeping note: earlier drafts of this entry recorded `1494`/`1495` — those were `-m "not tutorial"` subset runs that dropped the 21 tutorial tests, spuriously reading below main's prior full-suite `1506`; the true full count `1516` is `+10` over `1506`, consistent with the added GT3a tests.)* GT3 marked **partial** (GT3a landed / GT3b open) across WP-07 + the registry. **WP-07 remaining: GT3b** (ion `S`-adapter — first `iontrap-structure` cross-repo consumer, separate scoped decision), **GT6** (optional locally-symmetric `E_F`). Bundled the GT5 "vacuum/zero-occupation, not every pure state" documentation correction (docstring + tests + this logbook's GT5 entry).
